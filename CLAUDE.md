# VСмске (VС)

Социальная сеть в духе ВКонтакте. Интерфейс полностью на русском языке.

## Версия 9.0 — сайт написан заново
По просьбе владельца сайт переписан с нуля (старый `app.js` + `style.css`/`material.css`/`paper.css`/`player.css` удалены, их код не использовался).
База Firebase и правила **те же**: документы пишутся ровно в том формате, что и раньше, поэтому старые записи, чаты, треки и видео видны, а правила менять не нужно.
В 9.0 входит главное: вход (почта и Google), профиль, лента, записи (фото, опросы, репосты, комментарии, лайки), друзья и заявки, сигналы, поиск людей и хэштегов,
чаты (фото, голосовые, видеокружки — только просмотр, ответы, реакции, правка), звонки голосом и по видео, музыка, видео и клипы.
Мелких сервисов прежних версий (Радио, Погода, Игры, Маркет, Эфир, Сообщества, Истории и т. д.) в 9.0 **нет** — по решению владельца; их данные в базе остались нетронутыми.

## Как устроено
- Чистый HTML/CSS/JS без сборки и без npm: `index.html`, `css/app.css`, ES-модули в `js/` (`main.js` подключает все разделы).
- Firebase JS SDK 10.12.2 подключается из `https://www.gstatic.com/firebasejs/...` (`js/fb.js` — настройки проекта, ключ Google `GOOGLE_CLIENT`, `errText()` — ошибки по-русски).
  `localStorage vs_emu = '1'` подключает сайт к локальным эмуляторам (8080/9099) — только для проверки.
- Модули:
  - `js/lib.js` — без зависимостей: шаблон `html```…`` (всё экранируется само, `raw()` — вставить разметку как есть), `morph()` — бережное обновление DOM,
    даты/числа (`ago`, `dayLabel`, `fmtDur`, `plural`), `richText()` (ссылки, #теги → `search/%23тег`, @ники → `@ник`), `extractTags`, `extractMentions`, `buildSearch` (формат `users.search`),
    сжатие фото `compress(file, сторона, символов, квадрат)`, `safeImg`/`safePhoto`, иконки `I` (SVG), `toast`, `lsGet/lsSet`, `copyText`.
  - `js/core.js` — ядро: `VERSION`, `BASE`/`siteUrl`, состояние `S`, кэш людей `cache`/`U(uid)`/`ensureUsers()`, роутер, `render()`, каркас `shell()`, тема.
  - `js/auth.js` — вход/регистрация/Google, анкета нового человека (`@onboarding`), живые подписки (`chats`, `notifs`, заявки) → `onData('chats'|'notifs'|'me', fn)`.
  - `js/posts.js` — записи: `postCard`, `composer`, `watchPosts(запрос)` (живые страницы по 20 + «Показать ещё»), комментарии, `notify()`, просмотр фото; страницы `feed`, `post`.
  - `js/profile.js` — `nick`/`id` (профиль), `edit`, `settings`, `more`, быстрый поиск (окно, клавиша «/») и страница `search/<запрос>`.
  - `js/friends.js` — заявки и кнопки дружбы, страницы `friends[/requests|/find|/<uid>]` и `notif`.
  - `js/chats.js` — `im[/<uid или g_id>]`, `sendMessage(кому, текст, доп. поля)`; `js/calls.js` — звонки (экран `#call` вне `#app`).
  - `js/music.js` — `music[/my|/t_<id>]`, плеер (мини-панель и полноэкранный); `js/video.js` — `video[/<id>]`, `clips[/<id>]`; `js/files.js` — файлы кусками в Firestore.
- Как писать раздел: `view(имя, {title, enter(...args), leave(), render(...args), wide, full})` — страница `/<имя>/<args…>`;
  кнопки — `data-a="действие"` + `act('действие', (dataset, элемент, событие) => …)`; формы — `data-f` + `form('имя', (значения, форма) => …)`;
  поля с живым вводом — `data-i` + `onInput()`; окна — `modal(тип, fn)` + `openModal({type, …})`/`closeModal()`; подписки страницы — `sub(отписка)` (снимаются при уходе);
  то, что живёт поверх страниц (мини-плеер), — `shellExtra(fn)`; после каждой отрисовки — `onAfterRender(fn)`.
- Рендер: `render()` (раз в кадр) строит разметку и применяет её через `morph()`: элементы сопоставляются по `data-k`/`id`, введённый текст в полях не трогается
  (кроме полей с `data-v`), элементы с `data-keep` (видео, iframe, кружки) не пересоздаются — плеер не перезапускается.
- Адреса без решётки: `/feed`, `/im/<uid>`, `/@ник`, `/video/<id>`, `/clips/<id>`, `/music/t_<id>`, `/search/<запрос>`. `go(путь)`; в `href` пиши путь без «/» в начале — ссылки на свой сайт
  открываются без перезагрузки. GitHub Pages про такие адреса не знает: `404.html` перекидывает `/vsmske/video` → `/vsmske/?/video`, скрипт в начале `index.html` возвращает адрес и ставит `<base href>`.
  Старые ссылки с решёткой (`/#video` из старых записей) `route()` превращает в новые. Возврат от Google (`#id_token`) обрабатывает `auth.js`.
- Вход через Google: всплывающее окно (`signInWithPopup`); если оно заблокировано или сайт открыт с иконки — переход на accounts.google.com (`response_type=id_token`) и возврат на корень сайта.
  Адрес `https://nlponae269.github.io/vsmske/` добавлен владельцем в Google Cloud → Credentials → Web client → Authorized redirect URIs.
- Дизайн «Тёплый» (`css/app.css`): кремовый фон, коралловый акцент `--acc`, шрифт Manrope, светлая и тёмная тема (`data-theme` на `<html>`, localStorage `vs_theme` = `light`|`dark`|авто).
  Компьютер — боковая панель `.side` (на 761–1100px — узкая), телефон — верхняя строка `.top` и нижние вкладки `.tabs`. Все цвета — только через переменные в начале файла.
- Звонки (`calls.js`): запись `streams` с `mode: 'call'`, `to`, `title`; позвать — уведомление `type: 'call'`; принимающий пишет в `streams/{id}/peers/{id}` `offer`, звонящий отвечает `answer`;
  «Отклонить» — `offer: 'no'`. SDP без trickle, STUN Google + бесплатный TURN Open Relay. По окончании звонящий пишет в переписку «📞 Звонок · 1:23» или «Пропущенный звонок».
- Музыка: «Поток» — все треки платформы от новых к старым страницами по 50; «Мои треки» — `users.tracks` (сохранённые) + свои загрузки. Загрузка до 30 файлов сразу,
  название/исполнитель/обложка — из тегов ID3v2 (старые русские теги — cp1251) или из имени «Исполнитель - Песня». Плеер: очередь, повтор (`vs_repeat`), перемешивание (`vs_shuffle`),
  громкость (`vs_vol`), экран блокировки (Media Session), текст песни.
- Видео: файл до 20 МБ (кадр-обложка и длительность считаются в браузере) или ссылка YouTube / Rutube / VK Видео / .mp4; просмотры (+1 через 3 с, в клипах — через 2 с), лайки, комментарии.
  Клипы — те же `videos` вертикальной лентой со scroll-snap, играет только видимый, двойной тап — «нравится», ↑/↓ и M на клавиатуре.
- Забаненные (`users.ban`, `isBanned()` в `core.js`): кэш людей (`cache.users.set`) пропускает каждый профиль через `maskUser()` — для всех, кроме самого человека,
  имя «Deleted Account», аватарка-призрак (`.av.ghost`), без ника и сведений. Их фото в записях и сообщениях, голосовые, кружки, треки, видео и клипы заменяются
  заглушкой `locked()` («Фото недоступно»…) и не скачиваются (`hidden(uid)`); текст записей и комментариев остаётся. Профиль из базы клади в кэш и бери обратно через `U(id)`.
- PWA: `manifest.webmanifest`, `sw.js` (сеть в приоритете, кэш — только без интернета; Firebase не кэширует), иконки `icon-*.png`, `apple-touch-icon.png`.
- Firebase-проект `vsmske`: Authentication (почта+пароль и Google) и Firestore. Хостинг: GitHub Pages, `https://nlponae269.github.io/vsmske/`
  (домен `nlponae269.github.io` добавлен в Firebase → Authentication → Authorized domains).
- Тариф Firebase Spark (бесплатный). **Firebase Storage не используется**: фото — dataURL JPEG прямо в документах (меньше 1 МБ),
  файлы видео и музыки — кусками по 700 000 символов base64 в `files/{id}/chunks/{0000..}` (`js/files.js`).

## Проверка (для Claude)
Сайт проверяется в Chromium (Playwright) против эмуляторов Firebase: сервер, отдающий `index.html` на любой адрес (как `404.html` на GitHub Pages), плюс
`npx firebase emulators:start --only firestore,auth` с `firestore.rules`; в браузере `localStorage.vs_emu = '1'`. Тесты правил — как раньше (см. ниже).

## Android-приложение (папка `android/`)
**Заморожено по решению владельца — не обновлять и не дорабатывать, пока он сам не попросит.**
Настоящее нативное приложение (Kotlin + Jetpack Compose), не обёртка над сайтом. Работает с той же базой Firebase и пишет
документы **ровно в том же виде, что сайт** — правила Firestore для него не менялись. Если меняешь формат записи на сайте, поправь и `android/.../data/Repo.kt`.
- Подключение — настройками веб-приложения в коде (`data/Fb.kt`), без `google-services.json` и без регистрации в консоли.
- Что есть: вход/регистрация (почта+пароль), лента (друзья/все, фото, опросы, лайки, комментарии), профиль и правка, друзья и заявки,
  поиск людей, чаты (личные и беседы, фото, голосовые с сайта играются), сигналы, музыка (мои/все, загрузка mp3 с тегами и обложкой,
  добавить чужой трек к себе, фоновое воспроизведение Media3 с управлением в шторке, полноэкранный плеер с текстом песни и очередью).
- Liquid glass (`ui/Glass.kt`): содержимое экрана пишется в `GraphicsLayer` (`glassSource`), шапка/док/мини-плеер (`GlassPanel`) рисуют его под собой
  через AGSL-шейдер `LENS` (Android 13+; та же формула, что `lensMap()` на сайте). Android 12 — размытие, ниже — матовая заливка.
- Треки играются через `music/FirestoreDataSource.kt`: адрес `vsmske://file/<id>` → куски из `files/{id}/chunks` склеиваются в файл в кэше.
- Сборка: GitHub Actions (`.github/workflows/android.yml`) при изменении `android/` в main собирает APK и кладёт в релиз с тегом `android`
  (ссылка `releases/download/android/VSmske.apk` — на неё ведёт кнопка «Скачать APK» в настройках сайта, `androidCard()`). Перед каждым изменением
  приложения поднимай `versionCode`/`versionName` в `android/app/build.gradle.kts`.
- Ключ подписи `android/app/vsmske.jks` лежит в репозитории намеренно (ставится не из Google Play; обновление требует того же ключа).
- Проверка локально: `cd android && ./gradlew assembleRelease testReleaseUnitTest` (нужны JDK 17+ и Android SDK). Сборка с `-Pemu=true`
  подключается к локальным эмуляторам Firebase (10.0.2.2:8080/9099) — только для проверки.

## Коллекции Firestore
Описание данных — общее для всех версий (в базе лежат и данные разделов, которых в 9.0 нет; их не трогаем).
`users`, `usernames` (уникальные короткие имена), `friendRequests` (id = `от_кому`), `posts` + `posts/{id}/comments`,
`chats` (id = `uid1_uid2` по алфавиту) + `chats/{id}/messages`, `videos`, `files` + `files/{id}/chunks`,
`albums`, `photos` (миниатюры), `photoFull` (полные фото), `notifs` (уведомления: `to`, `from`, `type`, `postId`, `text`),
`groups` (сообщества: `name`, `about`, `photo`, `cover`, `ownerId`, `admins[]`, `membersCount`),
`reports` (жалобы, id = `тип_цель_автор`; читает и удаляет только админ),
`stories` (истории на 24 часа: `ownerId`, `image`, `text`, `views{uid: время}`; просроченные свои удаляет клиент владельца),
`users/{uid}/guests/{кто}` (гости страницы: `at`; видит только хозяин; пишется не чаще раза в 30 минут на страницу),
`questions` + `questions/{id}/answers` (ВС Ответы: `title`, `text`, `category`, `answersCount`, `bestId`; ответы с `likes`),
`mail` (ВС Почта: `from`, `to`, `subject`, `text`, `read`, `delFrom`, `delTo`; документ стирается, когда удалили оба; адрес — `ник@vsmske`),
`notes` (ВС Заметки: личные, `ownerId`, `title`, `text`, `color`, `pinned`),
`tracks` (ВС Музыка: `ownerId`, `title`, `artist`, `fileId` → `files` с `kind: 'music'`, `duration`; `users.tracks` — добавленные себе чужие треки),
`events` (ВС События: `title`, `text`, `place`, `at`, `cover`, `going[]`),
`playlists` (ВС Музыка 6.3: свои плейлисты), `streams` + `streams/{id}/peers|nodes` (ВС Эфир 6.8; с `mode: 'call'` — звонки 8.0), `videos/{id}/comments` (8.0), `gifts` (подарки: `from`, `to`, `gift` — ключ из `GIFTS`, `text`), `market` (ВС Маркет: `title`, `price`, `category`, `city`, `text`, `image`, `sold`).
Поля треков: `tracks.lyrics` (текст песни до 20 000 символов, может быть с тайм-кодами LRC `[мм:сс.сс]`) и `tracks.cover` (обложка, dataURL до 300 000) — ставятся отдельной правкой
после создания (правило create их не принимает), меняет только автор трека.
@упоминания в записях и комментариях дают уведомление `mention`.

Поля, добавленные в 1.3: `users.lastSeen` (статус «в сети», пишется не чаще раза в 4 минуты),
`posts.editedAt` (запись изменена автором), `chats/{id}/messages.image` (фото в сообщении, dataURL до `MAX_MSG_IMG`).

Поля, добавленные в 1.4: `posts.poll` (`{q, options[2..6], votes: {uid: номер}}`), `messages.replyTo` (`{id, from, text}`),
`users.pinned` (закреплённая запись), `users.cover` (ключ из `COVERS`), `users.notifSeenAt` (когда смотрел уведомления).
Уведомления пишутся «по возможности» отдельной записью (`notify()`), лайк — с id `like_<post>_<uid>`, снимается при снятии лайка.
Поля 1.5:
- `users.admin` (`true` boolean или строка `"true"` — администратор сайта, см. `isAdm()` и `isAdmin()` в правилах). **Ставится только вручную в консоли Firestore**, правила не дают изменить его с сайта.
  Админ может удалять любые записи, комментарии, видео и сообщества; у него особый дизайн профиля и значок ✓ у имени.
- `users.groups` (подписки на сообщества, до 500). Подписка = в одной пачке `users.groups` и `groups.membersCount` ±1.
  Записи сообщества лежат в `posts` с `wallId = groupId` и полем `groupId`; писать могут только `groups.admins`.
- `messages.audio` (голосовое, dataURL `data:audio/...` до ~500 КБ, до 60 с) и `messages.dur` (секунды).
Поля 1.7:
- `users.ban` (`{until: timestamp|null, reason, by, at}`, null — навсегда). Ставит и снимает только админ с сайта (не другому админу).
  Правило `notBanned()` запрещает забаненному создавать записи, комментарии, сообщения, сообщества, заявки, видео, файлы, альбомы, жалобы, лайкать и голосовать.
- `users.blocked` (чёрный список, до 500): `blockedBy()` в правилах не даёт заблокированному писать сообщения, комментировать записи, писать на стене и слать заявки.
- `messages.reacts` (`{uid: эмодзи}` из `REACTS`), `posts.repostOf` (id оригинала) и `posts.reposts` (счётчик, только +1).
Поля 1.8:
- Беседы лежат в `chats` с id `g_<случайный>`: `group: true`, `name`, `ownerId`, `members[]` (до 50). Личные диалоги — как раньше (`uid1_uid2`).
  В адресе и коде диалог задаётся «ключом»: uid собеседника или id беседы (`chatKeyId()`, `isRoom()`).
- `messages.fwd` (`{from, name, text}`) — пересланное сообщение; фото и голосовое копируются в само сообщение.
- `comments.likes`, `posts.images` (2–4 фото, каждое сжато до ~880 КБ / n), `posts.tags` (до 10 хэштегов, `extractTags()`), `users.bday` (`ГГГГ-ММ-ДД`).
Поля 3.0: `users.emoji` (эмодзи-статус у имени), `users.listening` (`{title, artist, at}` — «сейчас слушает», пишет плеер; выключается в настройках, localStorage `vs_listen`).
Поля 3.2 — коллекционные юзернеймы: `usernames/{ник}.col: true`. Выпускает только админ (себе или любому, от 1 символа) в админ-панели;
владелец может подарить его (меняется `uid`), сделать основным (`users.nick` без новой записи) или отказаться. Основной ник подарить и удалить нельзя.
Обычный человек занимает ник от 4 символов (`NICK_RE`), админ — от 1 (`NICK_ANY`); старые ники из 3 символов остаются. Коллекция на профиле —
запрос `usernames where uid ==`. Уведомление о подарке — тип `nick`.
Поля 2.1: `messages.edited` (сообщение исправлено), `users.saved` (закладки, id записей, до 500).
Уведомлений читается последние 150 на человека.

Составные индексы (созданы в консоли):
- `posts`: authorId ASC + createdAt DESC;
- `posts`: wallId ASC + createdAt DESC;
- `chats`: members ARRAY_CONTAINS + lastAt DESC.

Остальные запросы специально написаны так, чтобы не требовать новых индексов (сортировка на клиенте).

## Правила безопасности
Действующие правила вставлены вручную в консоли Firebase (Firestore → Rules), их копия лежит в `firestore.rules`.
Если меняешь структуру данных, обнови этот файл и напомни владельцу вставить его в консоль и нажать Publish.

**В консоль вставляется `firestore.min.rules`**, а не `firestore.rules`: вставка с телефона обрезает текст после 20 000 символов.
Правь только `firestore.rules`, потом запускай `python3 tools/minify-rules.py` (сокращает имена функций и параметров, склеивает строки, убирает `signed()` там, где следующая проверка и так требует входа) (он пересобирает `firestore.min.rules`
и ругается, если вышло больше 19 600 символов — жёсткий предел вставки 20 000) и прогоняй тесты на обоих файлах (`RULES_FILE=firestore.min.rules`).
Владельцу давай ссылку на raw-файл `firestore.min.rules` или страницу с кнопкой «Скопировать».

Защита (2.1): картинки в базе — только загруженные фото `data:image/(jpeg|png|webp|gif);base64,…` (`imgOk()`),
аватар ещё может быть фото Google (`photoOk()`); цвет — `#RRGGBB` (`colorOk()`); в профиле только известные поля (`keys().hasOnly`).
На сайте аватар показывается через `safePhoto()`, а всё, что пришло от пользователей, — через `esc()`/`linkify()`.

Правила строгие: для каждой коллекции перечислены допустимые поля (`keys().hasOnly`) и их размеры,
лайки можно менять только на себя, друзья — только по заявке, ник — только вместе с профилем в одной пачке.
Поэтому **любое новое поле или новая запись в `js/*.js` требует правки `firestore.rules`**, иначе будет `permission-denied`.

Проверка правил в эмуляторе (для Claude, владельцу не нужна; нужны Node.js и Java):
`cd tests && npm i && npx firebase emulators:exec --only firestore --project demo-vsmske "node --test"`.
При изменении правил или записей в `js/*.js` добавляй тест в `tests/rules.test.mjs` и запускай его.

## Как владелец обновляет сайт
Владелец работает **с планшета**, без терминала: загружает файлы на GitHub через браузер (Add file → Upload files).
- При каждом изменении кода или стилей поднимай версию в `index.html` (`css/app.css?v=X.Y`, `js/main.js?v=X.Y`), константу `VERSION` в `js/core.js`
  и имя кэша в `sw.js` (`vs-X.Y`), иначе браузер покажет старую копию.
- Файлы лежат в папках `js/` и `css/`: при загрузке через браузер их нужно класть в те же папки (на GitHub можно перетащить папку целиком).
- Объясняй шаги простыми словами, без команд терминала.

## Ограничения
- Видео-файл до 20 МБ, файл Диска до 10 МБ (константа `LIMITS`).
- Бесплатная квота Firestore: 50 000 чтений и 20 000 записей в день, 1 ГБ данных. Не добавляй ничего, что требует платного тарифа.
- Настройки приватности проверяются и в интерфейсе, и в правилах: на чужой стене пишут только друзья
  (и не пишут, если `privacy.wall == 'me'`); при `privacy.messages == 'friends'` новый диалог может начать только друг,
  уже начатый диалог продолжается.
