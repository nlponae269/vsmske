# VСмске

Социальная сеть в духе ВКонтакте. **Версия 9.0 написана с нуля**: новый код, новый дизайн «Тёплый» (кремовый фон, коралловый акцент, светлая и тёмная тема),
удобная раскладка на компьютере (боковая панель) и телефоне (нижние вкладки). База и правила доступа — прежние, все старые данные на месте.

Что есть: вход по почте и через Google, профиль с обложкой и правкой, лента друзей и всех, записи с фото (до 4), опросами, хэштегами и @упоминаниями,
лайки, комментарии, репосты, друзья и заявки, сигналы (уведомления), поиск людей и записей по #хэштегу, чёрный список и приватность,
чаты (фото, голосовые, ответы, реакции, правка, «прочитано», Избранное), звонки голосом и по видео прямо из чата,
ВС Музыка (Поток всей музыки, Мои треки, загрузка сразу нескольких MP3 с тегами и обложкой, мини-плеер и полноэкранный плеер, текст песни),
ВС Видео (свои ролики до 20 МБ и ссылки на YouTube, Rutube, VK Видео; просмотры, лайки, комментарии) и ВС Клипы (вертикальная лента, двойной тап — «нравится»).
Ставится на телефон и планшет как приложение.

**Приложение для Android** (папка `android/`, сейчас не обновляется): [VSmske.apk](https://github.com/nlponae269/vsmske/releases/download/android/VSmske.apk).

Сайт: https://nlponae269.github.io/vsmske/

Всё работает на бесплатном тарифе Firebase Spark: фото и файлы хранятся прямо в Firestore
(Firebase Storage не нужен).

## Из чего состоит

```
index.html        страница
css/app.css       оформление (светлая и тёмная тема)
js/               логика по разделам: core (ядро), auth (вход), posts (записи), profile, friends,
                  chats, calls (звонки), music, video (видео и клипы), files, fb (Firebase), lib (общее)
404.html          открывает сайт по «глубоким» адресам (…/vsmske/video) на GitHub Pages
firestore.rules   правила доступа к базе; в консоль вставляется сжатый firestore.min.rules
manifest.webmanifest, sw.js, icon-*.png   установка сайта как приложения
tests/, tools/    проверка и сжатие правил (для разработчика, сайту не нужны)
```

## Как обновить сайт

1. На GitHub откройте репозиторий → **Add file → Upload files**.
2. Перетащите изменённые файлы (`index.html`, папки `js` и `css`, `sw.js`) и нажмите **Commit changes**.
3. Через 1–2 минуты GitHub Pages покажет новую версию. Номер версии виден внизу страницы «Настройки».

## Как сделать человека администратором

1. Firebase → **Firestore Database** → вкладка **Data** → коллекция `users`.
2. Найдите документ человека (у него в поле `nick` его короткое имя).
3. **Add field**: имя `admin`, тип `boolean` и значение `true` (или тип `string` и значение `true`) → **Add**. Кнопка Add может быть за правым краем экрана: поверните телефон горизонтально.

Чтобы снять права, удалите поле или поставьте `false`. С самого сайта стать админом нельзя.

## Коллекционные юзернеймы

Уже выданные короткие имена продолжают работать (адрес страницы `…/vsmske/@ник`). Админ-панели, где их выпускают, в 9.0 пока нет.

## Как обновить правила доступа

1. Откройте https://console.firebase.google.com → проект **vsmske** → **Firestore Database** → вкладка **Rules**.
2. Удалите весь текст и вставьте содержимое файла **`firestore.min.rules`** (это сжатая копия `firestore.rules`: с телефона вставляется не больше 20 000 символов).
3. Нажмите **Publish**.

## Что включено в консоли Firebase

- Authentication → Sign-in method: «Email/Password» и «Google».
- Authentication → Settings → Authorized domains: `nlponae269.github.io`.
- Firestore → Indexes: три составных индекса (см. `CLAUDE.md`).

## Данные в Firestore

| Коллекция | Что хранит |
|---|---|
| `users/{uid}` | имя, короткое имя, город, статус, о себе, аватар, друзья, приватность, когда был в сети |
| `usernames/{nick}` | кому принадлежит короткое имя (`col: true` — коллекционное) |
| `friendRequests/{от_кому}` | заявки в друзья |
| `posts/{id}` + `comments` | записи на стене и комментарии |
| `chats/{uid1_uid2}` + `messages` | диалоги и сообщения (текст и фото) |
| `groups/{id}` | сообщества: название, описание, фото, обложка, владелец, админы, число подписчиков |
| `reports/{id}` | жалобы на записи, людей и сообщества (видит только админ) |
| `stories/{id}` | истории на 24 часа |
| `users/{uid}/guests/{id}` | гости страницы |
| `questions/{id}` + `answers` | ВС Ответы |
| `mail/{id}` | ВС Почта |
| `notes/{id}` | ВС Заметки (личные) |
| `tracks/{id}` | ВС Музыка: название, исполнитель, обложка, текст песни (файлы — в `files`) |
| `gifts/{id}` | подарки |
| `market/{id}` | ВС Маркет |
| `events/{id}` | ВС События |
| `notifs/{id}` | уведомления: кто, кому, что сделал (лайк, комментарий, запись на стене, дружба) |
| `videos`, `files` + `chunks` | видео и файлы Диска (файлы кусками) |
| `albums`, `photos`, `photoFull` | альбомы, миниатюры и полные фото |

## Ограничения бесплатного тарифа

50 000 чтений и 20 000 записей в день, 1 ГБ данных.

## Звонки: если у кого-то не соединяется
Звук и видео идут напрямую между устройствами. Если прямое соединение не получается (мобильный интернет, строгие роутеры), используется бесплатный
ретранслятор Open Relay — он прописан в `js/calls.js` в константе `ICE`. Его можно заменить своим бесплатным (metered.ca или Cloudflare Realtime).

## Адреса сайта
Страницы открываются по обычным адресам: `…/vsmske/video`, `…/vsmske/music/stats`, `…/vsmske/@ник`, `…/vsmske/clips/<клип>` (раньше было `…/vsmske/#video`). Старые ссылки с решёткой
по-прежнему работают и сами превращаются в новые. Для этого в корне лежит `404.html`: GitHub Pages показывает её на любой адрес, которого нет в файлах, и она открывает сайт на нужном разделе.
Если когда-нибудь сайт переедет на свой домен — файлы `404.html` и скрипт в начале `index.html` подстроятся сами (они смотрят, есть ли в адресе папка `/vsmske/`).
